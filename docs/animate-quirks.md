# Animate / JSFL quirks (verified on Animate 2027, macOS)

- `fl.setActiveWindow(doc)` takes effect only after the Run returns. Create/activate in one Run, operate in the next.
- The Compiler Errors panel follows the active document. Tools that read it (`publish`, `test_movie`) activate the chosen document in a separate Run first.
- Save a new document with `fl.saveDocument(doc, fileURI)` (`doc.saveAs` does not exist). Animate normalizes `doc.pathURI` (`file:///Macintosh%20HD/...` on macOS), so never compare it to the URI you passed; use the returned value. Helpers: `createSavedAs3Document`, `closeDocumentByPath` in `server/scripts/smoke-lib.mjs`.
- The Test Movie Player is a window inside Animate. Leave it open for the user to close with its window button. In the prototype, Cmd+W after AppleScript window targeting may have closed a user's FLA. `fl.closeAllPlayerDocuments()` closes all Player windows by API semantics, not just the one launched by a smoke test (not tested here). Close only a disposable FLA by exact `pathURI` with `close(false)`.
- JSFL files are concatenated by `server/src/runtime/jsfl-bundle.ts`. Shared files hold top-level functions taking `timeline`/`document`/`ctx`; only entry files (`index.jsfl`, `tween.jsfl`, ...) open and close an IIFE, whose completion value is the Run result.
- `timeline.pasteFrames(offset)` after cutting a whole layer can extend that layer to the timeline-wide length with an empty trailing span. `shiftLayerFrames` removes it only when every trailing frame is verifiably empty.
- The JSFL host has no standard `JSON` global (`JSON is not defined`). Return primitives or delimiter-joined strings from a Run; build JSON on the Node side.
- Animate renames a layer called `static` to `static_idn`. Use another name in tests.
- Direct writes to a tween's middle frame change the start keyframe (classic) or insert a `Motion_X` keyframe (motion). Never write them.
- Direct assignment ignores layer locks. `edit_timeline` and `edit_elements` unlock and restore explicitly.
- `doc.modified` is always undefined; read the window title (a trailing `*`) via AppleScript instead.
- `fl.publishDocument` returns true even on compile errors; read `fl.compilerErrors.save(uri)` after it. See `docs/adr/0003-...`.
- Shape tween: setting `frame.tweenType = "shape"` on the start keyframe creates the span (middle frames read `shape`; the end keyframe reads `none`). `frame.tweenEasing` (-100..100) and `frame.shapeTweenBlend` (`distributive` | `angular`) read back what was written, also from middle frames. Animate does not validate the end keyframe (symbol or text end keyframes raised no error), so validate in JSFL. `timeline.createMotionTween` does not make shape tweens. No hint-related member exists on frames, elements or timelines (shape hints are not scriptable). `doc.group()` threw `関数 group() は現在使用できません。` in the spike; `isGroup`/`isDrawingObject` were `false` for raw shapes and for `addNewPrimitiveRectangle`/`addNewPrimitiveOval` elements (`elementType === "shape"`), so primitives pass the raw-shape guard and Animate accepts the tween; whether it renders as a proper morph is unchecked. The `true` cases are unverified: `doc.group()`, `union`, `crop` and `punch` all threw `関数 … は現在使用できません。` and `doc.objectDrawingMode` is undefined, so no group or drawing object could be created.
- Real-Animate runner for ad-hoc JSFL: `node <tmp>/run.mjs file.jsfl`. Smoke scripts: `server/scripts/smoke-*.mjs` (shared setup in `smoke-lib.mjs`); `node server/scripts/smoke-run.mjs [--entrances] steps.json` runs ordered tool calls (`[{tool, args?, expectError?}]`) in a disposable AS3 document. `--entrances` dispatches through `execute_readonly` / `execute_write` but does not test a client's approval dialog; setup and cleanup use direct `run_jsfl`. Run after `npm run build` with Animate running.

## Additional DOM probes (Animate 2027, macOS; AS3 and HTML5 Canvas)

- `doc.addNewText({left, top, right, bottom})` adds a text element and returns `undefined`; the element reports `elementType === "text"`, while `instanceType` is `undefined`. Use `setTextString(str)` / `getTextString()` to replace/read the text. `textRuns[0].characters` also reads/writes the content. Style lives on `textRuns[0].textAttrs` (`size`, `face`, `fillColor`, `bold`, `italic`), and `setTextAttr(name, value)` works. `textType` accepts `static`, `dynamic`, `input` in AS3; Canvas accepts `static`/`dynamic` but rejects `input`. `alignment` accepts `left`/`center`/`right`/`justify`. AS3 only supports `lineType` on `dynamic`/`input` text (set `textType` first): `single line`, `multiline`, and `multiline no wrap`; setting or reading `lineType` on static text throws. Canvas rejects `single line` and accepts the other two on supported text types.
- `doc.importFile(fileURI, true, false)` returns `true` for PNG, WAV and MP3, adds them to the Library (item names retain the extension), and leaves the stage unchanged in both document types. `importFileToLibrary` is not a function on the Document, Library, or `fl` objects tested. A colliding import opens the modal `ライブラリの競合を解決` and blocks the Run; options are `既存のアイテムを置き換えない` (default) / `既存のアイテムを置き換える`, buttons `キャンセル` / `OK`. With the default + OK, the existing item remains and a second item appears as `<name> コピー` (e.g. `proto.png コピー`, `proto.wav コピー`, `proto.mp3 コピー`). Therefore check `doc.library.itemExists(name)` and refuse before calling `importFile`; do not let this modal block a tool Run.
- `doc.library.addNewItem("graphic", name)` returns `true`; the Library item reports `itemType`/`symbolType` `graphic`. `addItemToDocument({x, y}, name)` returns `true`; the stage instance reports `elementType` `instance`, `instanceType` `symbol`. On both AS3 and Canvas, `element.loop` reads/writes (`loop` → `play once`); `element.firstFrame` reads/writes when the graphic has multiple frames (0 → 2 after extending its timeline to 3 frames); `element.symbolType` reads/writes `graphic`. `element.swapElement` is not a function.
- In AS3 and Canvas, `width`, `height`, `frameRate`, and `backgroundColor` read/write and persist after `fl.saveDocument` and reopen. Resizing 550×400 to 640×360 left a stage instance at `x=50,y=60` unchanged. `library.duplicateItem(name)` returns `true` and names the copy `<name> コピー` in this locale; rename with `library.renameItem(newName, oldName)` (argument order is new name first). Usage can be found by scanning each timeline's layers/frames/elements and reading `element.libraryItem.name`; `library.editItem(symbolName)` enters a symbol timeline and its instances are found the same way.
- The swap API is `doc.swapElement(libraryItemName)`, not `element.swapElement`. In both AS3 and Canvas, select an instance with `doc.selection = [element]`; this adds to the current selection rather than replacing it, so call `doc.selectNone()` first to avoid swapping other selected instances. A successful call returns `undefined`, replaces the Library item, preserves x/y, scale, rotation, `loop`, and `firstFrame`, and leaves the old element reference valid (`oldElement === rereadElement` stayed true). Assigning `element.libraryItem = libraryItem` also swaps successfully and preserves those values. A nonexistent name throws `swapElement: 引数番号 1 は無効です。` without changing the instance; selecting a text element throws `「swapElement」には、範囲の選択が必要です。` and leaves the text unchanged. No modal appeared for success or these errors.

## Isolated Canvas Publish smoke

`server/scripts/smoke-isolated-publish.mjs` creates and saves a new HTML5 Canvas document in a fresh `os.tmpdir()` directory, adds a graphic Library item, publishes there, records the output file listing and `fl.compilerErrors` availability, then closes without saving and removes the directory. It refuses to run unless Animate is already running. Run with `npm run build && node server/scripts/smoke-isolated-publish.mjs`.

Verified on Animate 2027, macOS: `fl.compilerErrors` exists (`object`) and its `save` member is a `function`, but the Canvas `publish` tool reports `compilerOutput: "not_checked"` (compile errors remain unverified). Publish produced `<FLA stem>.html` and `<FLA stem>.js` alongside the saved FLA; no images directory appeared in this empty document. Exact listing from the run:

## Read-only inspection (verified on Animate 2027, macOS, AS3 and Canvas)

- Shape and text elements expose `x`, `y`, `width`, `height`, `scaleX`, `scaleY`, `rotation`, `matrix`, `left`, `top`; `skew` and `instanceType` are undefined for them. Symbol instances report `instanceType="symbol"`; graphic instances also expose `loop` and `firstFrame`.
- Symbol length: `item.timeline.frameCount` (Library item) and `element.libraryItem.timeline.frameCount` (stage instance).
- Tween middle frames: `frames[n].elements[0].x` only returns the interpolated value after `timeline.currentFrame = n`; with `currentFrame` elsewhere it returns the start value. `matrix.tx` is not interpolated. Reading inserted no keyframes. Restore `currentFrame` afterwards.
- A tested AS3 movie-clip instance returned finite `left`/`top` bounds but undefined `right`/`bottom` (serialized as `null`), even when its Library item contained a shape. Transform fields remained available.
- `doc.exportPNG(uri, true, true)` is byte-identical when the same frame is captured twice (SHA-256), and differs between different frames.
- `doc.exportPublishProfileString()` returns profile XML with enabled-format flags (`<flash>1</flash>`, `<html>1</html>`, ...) and file names, but no output directory; outputs land beside the FLA.
- A newly created, saved HTML5 Canvas document's profile uses `<publishFormat id="...">0|1</publishFormat>` flags paired with `<PublishProperties id="..." name="SVG Image|JavaScript/HTML">`; the `JavaScript/HTML` flag was `1` and `SVG Image` was `0`. Preflight can report those formats, but leaves output paths unchecked because filenames are stored as nested `<Property name="filename">` values and use a generated stem.

## AIR preflight and Android packaging (Animate 2027, AIR SDK 51.3.1, macOS)

- Verified with Desktop, Android and iOS sample FLAs: all report `doc.type === "Flash"`; `doc.playerTarget` distinguishes `AIR 51.3.1.2 for Desktop`, `Android` and `iOS`. `doc.getPlayerVersion()` returns `AdobeAIR_51.3.1.2`, `android_51.3.1.2` and `PFI_51.3.1.2` respectively. The adjacent descriptor is `<FLA stem>-app.xml`; the exported publish profile and FLA PublishSettings.xml did not contain signing or descriptor paths in these samples.
- On macOS, `doc.pathURI` may include `/Macintosh HD`; convert it in JSFL with `FLfile.uriToPlatformPath` before asking Node to inspect adjacent files. Node's `fileURLToPath` alone did not resolve that volume path.
- The Animate AIR SDK location was found in `~/Library/Application Support/Adobe/Animate 2027/ja_JP/Configuration/AIRSDK/AirSdkList.xml`. Check the installed SDK's `templates/air/Descriptor.<version>.xsd` when changing descriptor fixtures: in 51.3, `<resdir>` is a direct `<application>` child, not an `<android>` child.
- Verified on a Pixel 7 API 33 arm64 emulator using a disposable certificate and copied packaging inputs: `adt -target apk-captive-runtime -arch armv8` produced an AAB in this setup. `bundletool build-apks --mode=universal` produced an installable APK for `adb`. The generated launcher manifest referred to `@mipmap/icon`; `resdir/mipmap-anydpi-v26/icon.xml` was picked up as an adaptive launcher icon, while a differently named XML was not. An attempted `android:icon` override in `manifestAdditions` failed with ADT error 404. The launcher showed the masked icon. These observations do not establish behavior on other SDK versions, devices or release targets.
- The read-only `preflight_publish` checks descriptor/icon paths and reports signing as unchecked; it does not package an app or validate `Assets.car` contents. The iOS asset catalog's runtime behavior and signing remain unverified.
- With a disposable copy of the Desktop FLA and descriptor, opening the FLA, saving it after a document change, Publish (SWF/HTML output only), and closing it left externally edited `-app.xml` unchanged. The AIR settings dialog's OK is expected to rewrite the descriptor (user-reported, not verified here); signed AIR packaging and switching the FLA's platform target remain untested. Read/write tools target the adjacent descriptor or an explicitly supplied absolute `*-app.xml` path. `run_jsfl`-based platform switching has not been verified.
- In the disposable Publish probe, passing `/private/var/.../desktop.fla` as `document` failed with `Document not open`, while the returned `pathURI` included `file:///Macintosh%20HD/private/var/...`; use the returned URI or an unambiguous document name until the path matching is addressed separately.
